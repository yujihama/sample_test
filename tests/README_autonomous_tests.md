# エージェント間自律的連携テスト

このドキュメントでは、エージェント間の自律的な連携とツール利用を検証するテストの実行方法について説明します。

## 概要

`test_autonomous_use_case.py`ファイルでは、use_cases.mdに記載されているユースケースシナリオに基づいてエージェント間の自律的な連携をテストします。具体的には以下の2種類のシナリオをテストします：

1. **画像処理ツール利用ワークフロー**: 出張精算書類の検証中に不鮮明な領収書の印影や承認者の署名を確認するために画像処理ツールを利用するシナリオ
2. **エクセル解析ワークフロー**: 取引記録の検証で、エクセルデータを解析し、金額変更の正当性を確認するシナリオ

## テスト実装アプローチ

このテストでは、LLMを使用した各エージェントの自律的な判断と行動を検証します：

- **実際のLLM利用**: エージェントがLLMを使用して状況を理解し、次のアクションを自律的に判断
- **自律モード**: 各エージェントの自律モードを起動し、実際のエージェント処理を実行
- **応答待機**: エージェントがLLMを利用して判断・応答するのを非同期的に待機
- **完全自律検証**: 事前に決められた応答ではなく、LLMによる自律的な判断結果を検証

このアプローチにより、実際の運用環境に近い形でエージェント間の自律的な連携が機能するかを検証します。

## テスト内容

### 1. ツール利用ワークフロー (`test_tool_usage_workflow`)

このテストでは、以下のフローを検証します：

1. AgentAがAgentBに出張精算書類の検証を指示
2. AgentBが自律的に課題（不鮮明な印影や承認者署名）を特定し、ツール利用を提案
3. AgentAがツール実行を承認
4. AgentBがツールを実行し、結果を分析して報告

### 2. エクセル解析ワークフロー (`test_excel_analysis_workflow`)

このテストでは、以下のフローを検証します：

1. AgentAがAgentBに取引記録の検証を指示
2. AgentBが自律的にエクセル解析ツールを使用してデータを分析
3. AgentBが金額相違（申請額と承認額の差異）を発見し、問い合わせ
4. AgentAが規程情報を提供（金額変更の条件や権限）
5. AgentBが自律的に最終的な検証結果をAgentCに報告

## テスト実行方法

### 前提条件

- Python 3.7以上
- 必要なパッケージがインストール済み（pytest, pytest-asyncio, loguru等）
- 仮想環境が有効化されていること
- **LLMサービスへの接続が設定済み**（APIキーやエンドポイントが適切に構成されていること）

### コマンド実行

プロジェクトのルートディレクトリから以下のコマンドを実行します：

```powershell
# 全てのテストを実行
python -m pytest tests/smoke_tests/test_autonomous_use_case.py -v

# 特定のテストのみ実行
python -m pytest tests/smoke_tests/test_autonomous_use_case.py::TestAutonomousUseCase::test_tool_usage_workflow -v
python -m pytest tests/smoke_tests/test_autonomous_use_case.py::TestAutonomousUseCase::test_excel_analysis_workflow -v
```

### 詳細なログ出力

より詳細なログを確認するには、ログレベルを変更します：

```powershell
$env:LOG_LEVEL="DEBUG"; python -m pytest tests/smoke_tests/test_autonomous_use_case.py -v
```

## テスト結果の解釈

テストが成功すると、以下の内容が確認できます：

1. エージェントが自律的に状況を理解し、適切な判断を行っている
2. エージェント間のメッセージ交換が正常に機能している
3. LLMが適切に活用され、意思決定が行われている
4. ツールの提案と実行が適切に行われている
5. 複数のエージェントが協調して問題解決を行っている

テスト失敗時は以下の原因が考えられます：
- LLMへの接続問題やレスポンスエラー
- エージェントの自律モード実行に関する問題
- メッセージブローカーの問題
- タイムアウト（応答待機時間が不十分）
- ツールレジストリの設定問題

## 注意事項

- テスト実行には十分な時間が必要です（LLMの応答時間を考慮）
- タイムアウト設定は環境に応じて調整してください（max_wait_time変数）
- エージェントの自律モードは適切にクリーンアップされるよう設計されています
- テスト環境にはLLMサービスへの接続が必要です
- 結果を待機する際のポーリング間隔（asyncio.sleep）は必要に応じて調整してください

## トラブルシューティング

よくある問題と解決策：

1. **テストがタイムアウトする**
   - 解決策: `max_wait_time` の値を大きくする（LLMの応答時間によって調整）

2. **AssertionError: AgentBからの応答が受信されませんでした**
   - 解決策: 
     - LLMサービスの接続状態を確認
     - エージェントの自律モードが正しく開始されているか確認
     - メッセージの送信と受信が正しく行われているか確認

3. **エージェントの自律モード起動エラー**
   - 解決策: エージェントクラスのstart_autonomous_modeメソッドの実装を確認

4. **ツール実行エラー**
   - 解決策: ツールレジストリの設定とツール実装を確認

5. **LLM応答の品質問題**
   - 解決策: LLMのプロンプト設計やモデル選択、パラメータを調整する 

## 最近の修正と改善

### メッセージング修正（2023-03-21）

以下のエラーが解決されました：

1. **MessageType参照エラー**
   - エラー内容: `type object 'MessageType' has no attribute 'TASK_RESPONSE'`
   - 原因: `src/core/messaging.py`と`src/models/schema.py`に重複するMessageType定義があり、参照先が異なっていた
   - 修正: `MessageType.TASK_RESPONSE.name`を直接文字列 `"task_response"` に置き換え、依存性を削減

2. **送信パラメータ不一致エラー**
   - エラー内容: `MessageClient.send_response() got an unexpected keyword argument 'message_id'`
   - 原因: 実装されていた`send_response()`メソッドはパラメータ名が`in_response_to`であるのに対し、呼び出し側が`message_id`を使用
   - 修正: エージェントB側のパラメータ名を修正し、API仕様に準拠させた

これらの修正により、エージェント間の自律テストが正常に実行できるようになりました。`test_tool_usage_workflow`と`test_excel_analysis_workflow`の両方が成功するようになっています。

### エージェント状態遷移グラフの修正内容

各エージェントの状態遷移グラフについて、以下の点を修正しました：

1. `set_entry_point()` メソッドの呼び出し方法を統一
2. `compile()` メソッドの実行結果を変数に格納してから返すよう修正
3. フォールバック処理も同様にコンパイル結果を変数に格納してから返すよう修正

これらの修正により、エージェント間の連携動作の整合性が向上しました。 

## テスト自動実行と結果レポート生成

エージェント間の協力テストを自動実行し、結果をレポートとして生成するための機能を追加しました。これにより、エージェント間の連携が正しく機能しているかを包括的に評価できます。

### 機能の概要

1. **エージェントグラフの整合性確認**: すべてのエージェントグラフが正しく読み込まれ、初期化されることを確認
2. **エージェント間連携フローのテスト**: AgentA→AgentB→AgentC→AgentDの連携フローをテスト
3. **エラーハンドリングの検証**: 意図的なエラーに対する適切なハンドリングを確認
4. **チェックポイント機能の検証**: エージェントの状態保存と復元機能をテスト
5. **テスト結果の視覚化**: テスト実行結果を見やすいHTMLレポートで表示

### 使用方法

テスト実行とレポート生成は以下のコマンドで行えます：

```bash
# 仮想環境がある場合はアクティベートしてください
# Windows:
.\venv\Scripts\activate

# 統合テストを実行し、レポートを生成
python tests/run_tests_and_report.py --test-type integration

# 特定のテストファイルだけを実行
python tests/run_tests_and_report.py --test-file tests/integration/test_agent_e2e_workflow.py

# すべてのタイプのテストを実行
python tests/run_tests_and_report.py --test-type all

# レポート出力先を指定
python tests/run_tests_and_report.py --report-dir custom_reports
```

### レポート内容

生成されるレポートには以下の情報が含まれます：

- テスト実行の概要（成功/失敗/エラー数と成功率）
- 各エージェントのパフォーマンス指標（グラフ表示）
- 個々のテストの結果と詳細
- エラーが発生した場合のスタックトレース

レポートは `tests/reports/` ディレクトリに HTML ファイルとして保存されます。

以下のPythonパッケージが必要です：

- pytest
- matplotlib
- pandas
- jinja2
- loguru
