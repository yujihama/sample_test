# 疎通テスト（Smoke Tests）

## 概要

このディレクトリには、システムの基本的な機能が正常に動作していることを確認するための疎通テストが含まれています。疎通テストは、コードの改修や変更後に、主要な機能が引き続き正しく動作していることを迅速に確認するために使用します。

## 目的

1. システムの主要コンポーネントが基本的に機能していることを確認する
2. 改修時のデグレードを素早く検出する
3. CI/CDパイプラインの最初のステップとして使用する
4. 本格的な統合テストや総合テストの実行前に前提条件チェックとして機能する

## テスト構成

以下の主要コンポーネントに対する疎通テストを実装しています：

1. **データベース接続** (`test_db_connection.py`): データベースへの基本的な接続と操作が機能するかを確認
2. **APIエンドポイント** (`test_api_endpoints.py`): 主要なAPIエンドポイントが応答するかを確認
3. **エージェント基本機能** (`test_agents_basic.py`): 各エージェントの基本的な機能が動作するかを確認
4. **ワークフロー初期化** (`test_workflow_init.py`): ワークフローの初期化処理が正常に動作するかを確認
5. **エージェント連携ワークフロー** (`test_agent_workflow_e2e.py`): ユースケースに沿ったエージェント間連携とワークフロー実行の疎通を確認

### エージェント連携ワークフローテスト

`test_agent_workflow_e2e.py` には以下の4つのテストケースが含まれています：

- **基本的なエージェント間連携フロー**: エージェントA→B→C→Dの順に処理を実行し、各ステップの出力を検証
- **エージェント間のメッセージングシナリオ**: ユースケースに記載されているエージェント間のメッセージ交換パターン（指示→質問→追加情報→結果報告）を再現
- **APIを通したワークフロー実行**: APIエンドポイントを使用したE2Eワークフロー実行の疎通確認
- **人間介入を含むエージェントメッセージング**: エージェントが不確実性に直面した際に人間に質問し、回答に基づいて処理を継続するシナリオをテスト

このテストではユースケース（`docs/planning/use_cases.md`）に記載されている監査フローを忠実に再現し、エージェント間の連携が正しく機能していることを確認します。人間介入のテストでは、特に判断の難しい項目に対してエージェントが人間の判断を仰ぎ、その回答を適切に処理できるかを検証します。

## 実行方法

疎通テストのみを実行するには、以下のコマンドを使用します：

```bash
pytest tests/smoke_tests -v
```

特定の疎通テストのみを実行するには：

```bash
pytest tests/smoke_tests/test_db_connection.py -v
```

エージェント連携ワークフローテストのみを実行するには：

```bash
pytest tests/smoke_tests/test_agent_workflow_e2e.py -v
```

### pytestマーカーの使用

テストには以下のpytestマーカーが登録されています：

- **smoke**: 疎通テスト全般を対象
- **unit**: 単体テスト
- **integration**: 統合テスト
- **api**: APIエンドポイントのテスト
- **workflow**: ワークフローのテスト
- **human_interaction**: 人間の介入（問い合わせ・回答）を含むテスト

マーカーを使用してテストを実行するには：

```bash
# smokeマーカーが付いたテストのみを実行
pytest -m smoke

# workflowマーカーが付いたテストのみを実行
pytest -m workflow

# 人間介入を含むテストのみを実行
pytest -m human_interaction

# smokeマーカーが付いておらず、unitマーカーが付いたテストを実行
pytest -m "not smoke and unit"
```

これらのマーカーはテストコードに以下のように記述されています：

```python
@pytest.mark.smoke
@pytest.mark.workflow
def test_agent_workflow_basic_flow():
    # テストコード
```

## 注意事項

- 疎通テストはシステムの詳細な機能を検証するものではなく、基本的な機能が動作していることのみを確認します
- テスト実行時間は短く（1分以内を目標）、頻繁に実行できるように設計されています
- 失敗した場合は、より詳細なテストを実行する前に問題を解決する必要があります
- エージェント連携ワークフローテストは特にコードの改修後に実行し、エージェント間の連携や通信に問題がないことを確認することが重要です
